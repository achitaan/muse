A distinct possible mechanism is to replace tiny-path phase-B atomic norm accumulation with CTA-local RMS recomputation from the already-required FP32 ybuf inside the existing finalizer. It adds no launch or grid barrier. It is not the obsolete separate Marlin epilogue, and differs from changing routing construction or WGS occupancy. MAIN already uses a whole-row FINSS pass, but that implementation assumes NT512 and eight columns/thread; tiny uses NT256 and four column-parallel segments/token.

For tiny NT256,H4096,FINCOL1: FSEG=H/(NT*4)=4, so four output CTAs own each token's1024-column segments. Each active output CTA could read the full4096-element FP32 ybuf row for every local route, reduce in FP32 with the existing freed shared ring, then apply the original route weight/epsilon and output-store arithmetic to its own segment. Each CTA would cover16 values/thread for the norm. No last-CTA publication or additional global dependency would be needed: the existing phase-B grid join already makes every ybuf column visible.

Without vector reuse, additional logical reads are4*4096*4=65536 bytes per local route. The M8/all-local maximum is64 routes,or4MiB of additional logical L2 requests; these are not HBM measurements. Each CTA would need eight partial sums and at least(NW*8+8)*4=288 bytes of shared reduction storage for NW8,with source-verified ring lifetime/alignment and no spills. Actual register pressure,cache behavior and instruction cost are unresolved. No time saving is assumed; dynamic atomic counts and exposed contention have not been measured.

Required numerical boundaries remain: original NVFP4/scales and both GEMMs,Marlin-equivalent BF16 accumulator/global-scale/product boundaries,FP32 SiLU-and-multiply followed by BF16 inter,retained BF16 effective1+w gain multiplied into FP32 ybuf,full4096-element norm with epsilon1e-8,route weighting/reduction in FP32 and final BF16.
