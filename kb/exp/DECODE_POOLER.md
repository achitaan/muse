# DEC_POOL: one contiguous FP32-router copy per stage

Branch `loop/dec-pooler`, base `origin/argon/keell-base-20261102`.
Check file: `kb/exp/decode_pooler.py` (self-contained, generated by
`python3 kb/exp/build_decode_pooler.py`). No check submitted locally.

## Bytes and diagnosis

`sk2` streams exactly `4096*8192*12/8 = 50,331,648` pooler bytes.
Both the FP32 and BF16 hi/lo routers stream `256*8192*4 = 8,388,608` bytes.
Escapes add exactly `128*pmax*8` bytes; weight-dependent `pmax` is unavailable
from the supplied text profile. The check prints actual sizes as `DEC_POOL_BYTES`.
Weight floor at 4.8 TB/s: `12.2333867 + 0.0002133333*pmax` us, **not 11.7 us**.

Using 58,720,256 bytes before that small escape-table term, profile
`decode_attn_fp16.bc0b306ed55449a8.txt` gives:

| T | case | fused kernel us | effective weight TB/s | fraction of 4.8 TB/s |
|---|---|---:|---:|---:|
| 1 | d1S | 17.5 | 3.355 | 69.90% |
| 1 | d1F | 17.2 | 3.414 | 71.12% |
| 8 | v1S | 18.6 | 3.157 | 65.77% |
| 8 | v1F | 18.8 | 3.123 | 65.07% |
| 16 | d16S | 18.0 | 3.262 | 67.96% |
| 16 | d16F | 17.5 | 3.355 | 69.90% |
| 32 | d32S | 22.1 | 2.657 | 55.35% |
| 32 | d32F | 20.5 | 2.864 | 59.67% |

These are effective weight-stream rates, **not measured HBM bandwidth**.
The profile explicitly includes PDL waits in kernel duration. Input reads repeat
across CTAs and hit L2: pooler requests `128*M*8192*2` activation bytes; FP32
router requests `128*M*2048*4`, BF16 hi/lo router `128*M*2048*2`. At T=1 the
deferred boundary supplies M=2. Counting all these as HBM reads is incorrect.
Outputs: pooler `M*4096*2`, router `M*256*4` bytes, plus small router quarter
partials/counters. The 13.9-16.8 us ablation is a different observable from
17.2-22.1 us kernel wall time. Some apparent missing bandwidth is PDL overlap.

The grid is already 128 CTAs on 132 SMs (96.97% one-wave coverage), not a tail
wave. The small-T FP32 router **already interleaves** its four stages among
16 pooler stages. Ring depths are 6/5/3 at T<=8/16/32. Arithmetic, escapes and
dependency waits remain constraints; the profile alone cannot identify all
hardware stalls conclusively.

## The one change

At T<=8 the producer issues **eight separate 2-KiB bulk weight copies per router
stage**. Pack unchanged FP32 weight bits as `[j][tile][quarter][row][512]` in
prepare and replace these with **one 16-KiB copy**. Four router stages change
32 weight-copy commands per CTA to 4. Adjacent CTAs also stream adjacent ranges.
Shared-memory destination bytes, barriers, consumers, every FMA, escape order,
warp butterflies and quarter reduction remain identical. No approximation,
extra launch, counter change or reduction redesign.

T16/T32 are explicitly unchanged: their hi/lo router already uses a contiguous
copy. Non-admission records are printed; identical code is never selected on
timing noise. This lever does not apply to their bandwidth shortfall.

## Admission and validation

Default is incumbent. Admission requires exact pack/unpack and two fresh-input
whole-layer passes, identical expert IDs, bit-equal pooler/logits, final outputs,
residual and cache writes (stricter than judge tolerance), including a repeated
incumbent control. Each pass uses 12 measured ABBA/BAAB rounds plus two warm
rounds and a **512 MiB READ** flush before every sample, outside CUDA events.
Median/paired/both-order ratios must all be <=0.992; same-run base/base null
ratios must all be within [0.995,1.005], on both passes. All requested fields
are printed on `DEC_POOL` lines. Failed/incomplete cases retain incumbent.

Optional build runs in a thread alongside base prepare. Admission deadline is
280 s. Unrelated incumbent MFIN diagnostics are disabled; production MoE stays
unchanged. All load_inline calls explicitly use host/NVCC C++20 and SM90a.
No process creation or versioned CUDA graph APIs.

CPU: `python3 kb/exp/test_decode_pooler.py -v`, AST parse, forbidden grep.
GPU compilation/timing/judge validation are unverified until the caller's check.
Strict bit equality may reject valid candidates when unrelated incumbent
reductions are non-repeatable. No measured speedup claim before a GPU check.
